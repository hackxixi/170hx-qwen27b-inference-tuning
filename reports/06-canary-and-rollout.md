# 06 组合版金丝雀、生产 A/B 与滚动上线（2026-09-25）

**结论：** 组合版（vLLM 0.30 + int4 起草头 + int8 输出头）在单副本金丝雀上浸泡约 80 分钟、319 个请求，0 错误、0 Xid。同时段生产 A/B 相对 int8 输出头版：单流英 +12.2% / 中 +11.4%，8 并发英 +8.3% / 中 +5.7%。当天滚动上线到全部 7 个副本。

组合版的独立测试卡数据见 [04](04-decode-six-items.md)（代号 C1）。

## 1. 金丝雀
- 把 1 个生产副本换成组合版：
  - 镜像：vLLM 0.30（以 HyperQwen 0.29 镜像为底，装 vllm 0.30.0，再应用 [HyperQwen PR#189](https://github.com/syv-ai/HyperQwen/pull/189) 的补丁系列，自建）；
  - 模型：`-fast-head8-d3`（int8 输出头 + 单独存放的 int4 起草头，目录用相对 symlink 组装，见 [`patches/README.md`](../patches/README.md)）；
  - 补丁：[`qwen3_5_mtp.v030.diff`](../patches/d3-draft-head4/qwen3_5_mtp.v030.diff)，`MTP_DRAFT_HEAD4=1`；
  - 其余参数与生产 `hq.env` 相同。
- 它照常接网关的真实流量，与其他 6 个副本一起参与分发。
- 启动脚本见 [`deploy/run-replica-c1.sh`](../deploy/run-replica-c1.sh)。
- **回滚**：用原来的启动脚本（`run-replica.sh <名> <GPU-UUID> <端口>`，镜像与模型回到 `hq.env` 里的生产值）把这个副本重建一遍即可。组合版的模型目录只是旁边多出的一组 symlink，不影响原目录。

## 2. 浸泡
- 时长约 80 分钟，其中包括下文 3 轮满负载压测。
- 期间共 319 个请求：全部返回 200，非 200 为 0，Traceback / CUDA error 为 0，Xid 为 0，容器重启 0 次。
- 统计口径：容器日志（HTTP 状态、异常栈）加宿主机 journalctl（内核 Xid）。

## 3. 同时段生产 A/B
- **对照组**：组合版副本（C1）vs 另一个跑 int8 输出头的生产副本（H8，vLLM 0.28）。两个副本同时在接真实流量，所以两边的背景负载是同一批请求随机分到的，条件对两者更公平。
- **方法**：用 [`bench/abbench.py`](../bench/abbench.py) 跑 3 轮，每轮依次测 C1 和 H8 的 c1 / c8、中英文，每档 2 遍。c1 看每路 decode 中位 tok/s，c8 看聚合 tok/s；最终取每档 6 个值（3 轮 × 2 遍）的中位数。

### 3.1 汇总

| 档位 | 组合版 C1 | int8 输出头版 H8 | 提升 |
|---|---:|---:|---:|
| 单流 英 | 170.4 | 151.9 | **+12.2%** |
| 单流 中 | 137.4 | 123.4 | **+11.4%** |
| 8 并发 英（聚合） | 659.5 | 608.9 | **+8.3%** |
| 8 并发 中（聚合） | 540.2 | 511.0 | **+5.7%** |

### 3.2 逐轮数据（每格为该轮 2 遍的值）

| 档位 | 组 | 第 1 轮 | 第 2 轮 | 第 3 轮 | 6 值中位 |
|---|---|---|---|---|---:|
| c1 英 | C1 | 166.3 / 173.7 | 167.2 / 174.1 | 167.0 / 174.0 | 170.4 |
| c1 英 | H8 | 146.2 / 155.1 | 150.5 / 147.2 | 153.4 / 155.4 | 151.9 |
| c1 中 | C1 | 136.3 / 138.2 | 136.6 / 138.4 | 136.7 / 138.4 | 137.4 |
| c1 中 | H8 | 121.7 / 124.9 | 117.7 / 126.3 | 121.9 / 126.4 | 123.4 |
| c8 英 | C1 | 659.0 / 660.2 | 659.8 / 659.1 | 660.8 / 655.5 | 659.5 |
| c8 英 | H8 | 596.1 / 610.1 | 597.3 / 612.8 | 607.7 / 616.8 | 608.9 |
| c8 中 | C1 | 538.6 / 542.7 | 534.6 / 544.3 | 538.6 / 541.7 | 540.2 |
| c8 中 | H8 | 496.3 / 508.3 | 516.8 / 513.6 | 516.1 / 501.1 | 511.0 |

- 3 轮之间 C1 很稳（c1 英 166–174，c8 英 656–661）；H8 波动大一些（c1 英 146–155，c8 中 496–517）。
- 各档 C1 的最低值都高于 H8 的最高值（例如 c1 英 166.3 > 155.4，c8 英 655.5 > 616.8），差距不是由个别离群值造成的。
- TTFT 中位：c1 C1 0.155 s / H8 0.125 s，c8 C1 0.40 s / H8 0.345 s。组合版的首字略慢约 30–60 ms，原因本轮未查。
- 0 错误。

### 3.3 为什么比测试卡上的收益高
独立测试卡上，C1 相对 P 是 c1 +7.4 / +8.3%，c8 +4.9 / +5.9%（[04](04-decode-six-items.md)）。生产 A/B 高出 3–4 个百分点，可能原因：
- 两边都接着真实流量，H8 在背景负载下的波动更大（见上表），而 C1 的吞吐更稳；
- 测试卡和生产卡不是同一张，单卡之间有差异；
- 两次测试的基线不同（测试卡 P 是隔离的，这里的 H8 是带流量的）。
本轮没有进一步拆分这几项。

## 4. 滚动上线
- 2026-09-25，浸泡与 A/B 通过后，用 [`deploy/roll-c1.sh`](../deploy/roll-c1.sh) 把全部 7 个副本（分布在 2 个节点）逐个切换为组合版，约 30 分钟完成。
- 脚本每处理一个副本：
  1. 读出该容器绑定的 GPU UUID（按 UUID 绑卡，避免加卡后设备序号错位），用 `run-replica-c1.sh` 重建；
  2. 最多等 15 分钟，`/health` 返回 200；
  3. 发一条 `1+1=?` 试着出字，响应里必须有 `content`；
  4. 容器日志里必须同时出现 `head8-d3`、`v0.30`、`separate draft_head4` 三个标记。
  任何一项失败就停下（`exit 1`），不再动后面的副本。
- 多个副本串行启动。热缓存下每个副本约 2.5–7 分钟可以通过 `/health`。
- 网关配置不需要改：副本地址和 id 不变。本轮没有单独统计滚动期间网关侧的错误数。

## 5. 回滚方法
- **单个副本**：`run-replica.sh <名> <GPU-UUID> <端口>`，用 `hq.env` 里的生产镜像与模型重建。
- **全部副本**：把 [`roll-c1.sh`](../deploy/roll-c1.sh) 里的 `run-replica-c1.sh` 换成 `run-replica.sh`、日志标记换成 `fast-head8`（即 [`roll-head8.sh`](../deploy/roll-head8.sh)），逐个重建回 int8 输出头版。
- 组合版需要的镜像（`hyperqwen:v030`）、模型目录（`-fast-head8-d3`）、补丁文件都是新增的，回滚不需要删除任何东西。

## 6. 过程记录
1. **前置条件**：测试卡上 C1 相对 P 通用负载 +5~9%、开发场景 c1 decode +9.7%，贪心等价（[04](04-decode-six-items.md)）。上线条件定为：单副本浸泡 30 分钟以上，0 Xid、0 错误，再滚动。
2. **准备**：两个节点都导入 vLLM 0.30 镜像；在生产模型目录旁用相对 symlink 组装 `-fast-head8-d3`（除 index 外全部指向 `-fast-head8`，另放 626 MB 的起草头文件）；0.30 版补丁放到固定位置；新建一个独立的编译缓存卷，避免和 0.28 的缓存混用。
3. **金丝雀**：用 `run-replica-c1.sh` 重建一个副本，确认启动日志里 `head8-d3`、`v0.30`、`separate draft_head4` 三个标记齐全，`/health` 200，试出字正常，然后让它继续接网关流量。
4. **浸泡与 A/B**：浸泡期间穿插 3 轮 A/B（§3），每轮先测 C1 再测 H8。统计容器日志的 HTTP 状态码、异常栈，以及宿主机内核日志里的 Xid。
5. **滚动**：浸泡与 A/B 都通过后运行 `roll-c1.sh`，7 个副本逐个切换，每个都过了三项自检，没有一个触发停止。
6. **上线后**：回滚路径保持可用（§5），旧镜像和 `-fast-head8` 目录都保留。
