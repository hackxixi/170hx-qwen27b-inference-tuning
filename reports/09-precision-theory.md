# 09 理论精度推算（2026-09-24，并用 02 的实测验证）

这份报告把 [01](01-three-way-comparison.md) 里用到的精度推算单独展开：每种数值格式的误差有多大、各个组件的误差怎么传到输出、为什么只有「分岔 token」会被翻转，以及这些推算后来怎样被 [02](02-int8-lm-head.md) 的实测验证。

**结论：**
- 三套方案（现役 HyperQwen、170hx-fullstack 原方案、推理栈 + HyperQwen 模型）的量化保真度差距在 1–2 dB 量级，实际任务中难以区分。
- 现役最大的短板是 int4 输出头；把它换回 int8 以后，与 int4 版的 top1 一致率是 97.63%，分歧全部落在 top1 概率 0.17–0.60 的近平局上，和推算一致。
- 投机解码在理论上无损；KV fp8 只作用于 1/4 的层，总噪声约 +0.7%（但实测仍可测出，见 [08](08-kv-cache-quantization.md)）。
- 170hx-fullstack 的微调模型在它自带的评测上，与官方权重的差异都在约 1σ 以内。

## 1. 数值格式的重建误差（group=128 数值模拟）

做法：从给定分布里采样权重，按 group=128 分组量化再反量化，算相对重建误差 = 误差 RMS / 原值 RMS，括号里是对应信噪比 −20·log10(相对误差)。两种分布假设：
- 高斯分布；
- 自由度 5 的 t 分布（厚尾，更接近真实 LLM 权重里少数大值的情况）。

| 格式 | 用在哪里 | 高斯 | 厚尾 t5 |
|---|---|---:|---:|
| int4 对称 g128 | 现役主体、现役 `-fast` 的 lm_head、现役 MTP 头 | 11.1%（19.1 dB） | 16.2%（15.8 dB） |
| int4 非对称 g128 | 原方案主体（AWQ） | 10.1%（20.0 dB） | 13.3%（17.5 dB） |
| int8 对称 g128 | 现役 embed、基座 lm_head、原方案 33 个敏感模块 | 0.65% | 0.95% |
| fp8 e4m3（按张量） | 原方案与「推理栈 + HyperQwen 模型」的 KV | 2.65%；绝对值小于约 0.02 时升到 5.7% | — |
| bf16 | 基线 KV、原方案 lm_head | 0.17% | — |

- 对称网格把 [−max, max] 均分，非对称网格把 [min, max] 均分。厚尾分布下单组里一个大值会把对称网格撑宽，所以非对称的优势更大（高斯下误差小 9%，t5 下小 18%）。
- fp8 e4m3 是浮点格式，相对误差和数值大小无关，约 2.65%；但低于最小规格化数的值落进非规格化区间，有效位数骤减，没有校准 scale 时绝对值小于约 0.02 的 K/V 误差翻倍到 5.7%。

## 2. 各组件的误差分析

### 2.1 主体权重
- 原方案（AWQ，非对称 int4）比现役（AutoRound，对称 int4）的网格误差小 9%–18%。
- 原方案另把 33 个敏感模块升到 int8：约 2.4B 参数，约占主体的 10%，集中在第 6–62 层的 MLP gate/up（配置见其 `config.json` 的 group_1）。int8 的误差比 int4 小一个数量级以上，这部分可按 0 计。
- 合计的噪声能量比（原方案 / 现役）：
  - 高斯：(10.1 / 11.1)² × 90% = 0.828 × 0.9 ≈ **0.745**
  - t5：(13.3 / 16.2)² × 90% = 0.674 × 0.9 ≈ **0.607**
  - 即噪声能量约为现役的 **0.61–0.74**，RMS 为 0.78–0.86（低 14%–22%），信噪比高 10·log10(1/0.745) ≈ 1.3 dB 到 10·log10(1/0.607) ≈ 2.2 dB。
- 反向因素：AutoRound 做逐层误差最小化（对输出误差而不是权重误差做优化），通常优于 AWQ 的激活感知缩放，会抵消掉一部分。所以这一项算原方案小幅占优，量级 1–2 dB。

### 2.2 lm_head（输出头）
- 现役 `-fast` 把 1.27B 参数的输出头压到 int4（GPTQ 校准），AutoRound 基座原本是 int8，原方案是 bf16。
- 输出头的误差直接加在 logits 上，不经过后续层的平均。推导：
  1. 设第 i 个 logit 为 zᵢ = wᵢ·h，量化后 wᵢ + δᵢ，误差项 δᵢ·h。δᵢ 与 wᵢ 同分布量级，相对误差约 11%，所以误差项的标准差约为 logits 在词表上离散度的 11%（未校准时；GPTQ 用激活统计补偿，大致能减半）。
  2. 取 logits 离散度 2–3 nats，每个 logit 的噪声约 0.1–0.35 nats。
  3. 决定 argmax 的是两个候选的差值。两个独立噪声相减，标准差再乘 √2，约 **0.15–0.5 nats**。
- **「分岔 token」判据**：只有 top1 与 top2 的 logit 差小于约 0.5 nats 时，噪声才有可观的概率翻转两者。差 0.5 nats 意味着 p₁/p₂ = e^0.5 ≈ 1.65；即使只有两个候选，p₁ 也只有 1.65 / 2.65 ≈ 0.62。所以会被翻转的 token，其 top1 概率大约在 **0.6 以下**。
- 在数学、代码这类高置信输出里，top1 概率 >0.9 的 token 占大多数，这类 token 基本不受影响；受影响的是措辞选择一类的近平局。

### 2.3 KV cache（fp8）
- 这个模型 64 层里只有 16 层全注意力层有 KV cache，另外 48 层是线性注意力（GDN），状态保持 bf16/fp16。
- 单层噪声能量相对于 int4 权重噪声：(2.65 / 11)² ≈ 0.058，约 6%。
- 只作用于 1/4 的层：6% × 1/4 ≈ 1.45%，即总噪声能量增加约 1.5%。
- 折成 RMS：√1.0145 ≈ 1.0072，约 **+0.7%**，可以忽略。
- 唯一风险是 §1 提到的非规格化区间：没有校准 scale 时，小值 K/V 误差翻倍，长上下文下注意力分布更平，这一项可能被放大。实测（[08](08-kv-cache-quantization.md)）fp8 KV 的 tf 一致率比噪声底低 0.31 个百分点，long4k 低 1.36 个百分点，说明这一项在长输入下确实能测出来，只是量级小。

### 2.4 投机解码
- **贪心**：每一轮由目标模型对「前缀 + 草稿」做一次前向，逐位置取 argmax，与草稿不一致处截断，并补上目标模型在该处的 argmax。所以输出序列就是目标模型逐 token 贪心的结果，草稿只决定每轮能前进几个 token。
- **采样**：用拒绝采样。草稿 token x 以 min(1, p(x)/q(x)) 接受，拒绝时从 norm(max(0, p − q)) 重采。可以证明最终 token 的分布严格等于目标分布 p，与草稿分布 q 无关。
- 所以 MTP、DFlash2、suffix 草稿对精度的理论影响都是 0，只影响速度。
- 实测中「贪心输出不完全一致」只来自数值路径：验证批的形状不同（1 个 token vs 5 个 token）会走不同的 kernel 和累加顺序，bf16 下 logits 有 1 ulp 量级的差异，碰上 top1 与 top2 相差 ≤0.125 nats（bf16 logprob 的分辨率）的真平局就会翻。见 [04](04-decode-six-items.md) 的 gate / probe 结果。
- 旁证：推理栈 + HyperQwen 模型（SGLang + DFlash2）的输出开头与现役（vLLM + MTP）逐字一致。

### 2.5 微调（只有原方案有）
原方案换成了 EfficientThink（SFT + SimPO）微调模型，这一项无法用数值误差推算，只能看它自带的评测（`benchmark-comparison-v5.json`，动态 FP8 + DFlash2，开思考，max_tokens 32768）：

| 评测 | n | 官方权重 | 微调后 | 差 | 差的标准误 | 差 / 标准误 |
|---|---:|---:|---:|---:|---:|---:|
| GPQA | 198 | 82.83%（164） | 86.36%（171） | +3.5 | 3.6 | 0.97σ |
| MMLU | 500 | 90.2%（451） | 88.4%（442） | −1.8 | 1.95 | 0.92σ |
| LiveCodeBench | 100 | 69%（69） | 74%（74） | +5 | 6.4 | 0.78σ |

- 标准误按两个独立比例之差算：√(p₁(1−p₁)/n + p₂(1−p₂)/n)。例如 GPQA：√(0.828×0.172/198 + 0.864×0.136/198) ≈ 0.036。同一题集上的配对差会略小一些，但没有逐题数据，无法算配对标准误。
- **三项都在约 1σ 以内，统计上不显著**，而且方向不一致（两升一降）。
- 平均推理长度：GPQA 10,234 → 9,556（−6.6%），MMLU 1,114 → 1,010（−9.3%），LiveCodeBench 12,167 → 12,514（+2.9%）。「压缩思考」的效果有限。
- 这组评测是开思考做的。本仓库的所有测速都关思考，关思考下微调的影响没有数据。
- 评测用的是动态 FP8 权重，不是实际部署的 AWQ W4A16，量化本身的影响没有包含在内。

## 3. 汇总（相对原始 bf16 模型的保真度）

| | 主体权重噪声（RMS，现役 = 1） | 输出头 | KV | 投机解码 | 模型本身 |
|---|---|---|---|---|---|
| 现役（int4 输出头，09-24） | 1.00 | int4，**主要短板** | bf16 | 0 | 官方 |
| 原方案 | 0.78–0.86 | bf16 | fp8（+0.7%） | 0 | 微调，差异不显著 |
| 推理栈 + HyperQwen 模型 | 1.00 | int4 数值（反量化成 bf16 存储，数值不变） | fp8（+0.7%） | 0 | 官方 |
| **最终上线配置** | 1.00 | **int8** | bf16 | 0 | 官方 |

- 理论保真度排序：原方案 ≳ 现役 ≈ 推理栈 + HyperQwen 模型，差距 1–2 dB 量级。
- 按公开经验，W4 g128 相对 bf16 通常掉 0.5–1.5 分；两套方案之间的差距应是这个范围里的一小部分。
- 现役要补精度，最划算的是把 lm_head 换回 int8（基座原配置）。代价是每步 decode 多读约 0.6 GB 权重（1.27B 参数从 4 bit 到 8 bit），需要实测速度，见 [02](02-int8-lm-head.md)。

## 4. 实测验证：int8 输出头（数据来自 02）

把现役的 int4 输出头换成基座的 int8 输出头，其余全部不变，然后拿现役的贪心输出做 teacher forcing，逐位置比较 argmax。

| 推算 | 实测 | 是否吻合 |
|---|---|---|
| 候选差值噪声 0.15–0.5 nats，只有差值 <~0.5 nats 的 token 会被翻转 | 17 条贪心输出的首个分歧点上，现役侧 top1-top2 差值 0–0.625 nats（16/17 ≤0.25，只有 1 条 0.625） | 吻合 |
| 被翻转 token 的 top1 概率 <~0.6 | 分歧点 top1 概率：现役侧 0.17–0.56，int8 侧 0.17–0.60 | 吻合 |
| 高置信 token 基本不受影响 | tf top1 一致率 **97.63%**（13,193 / 13,513） | 吻合 |
| — | 同一配置自比（噪声底）99.45%（13,438 / 13,513） | — |

- 97.63% 对 99.45%，输出头量化本身带来的差异约 1.8 个百分点，大约每 55 个 token 有 1 处选词不同。
- 分歧首现位置的中位数是第 24 个 token：几乎每条输出在开头不久就会碰到第一个分岔 token，这符合「近平局在自然语言里很常见」的推算。
- int8 输出头跑两次，17/17 逐 token 全同，排除了 int8 版自身的不确定性。
- 基座原样（lm_head int8、MTP int8）与现役比，分歧点和 int8 输出头版几乎一样（17 条里 15 条分歧位置相同），说明分歧来自输出头，而不是 MTP 头的精度。

## 5. 复现
- 数值模拟：numpy 即可，按 group=128 分组，对称网格 scale = max|w| / 7，非对称网格 scale = (max − min) / 15。不同的舍入和截断细节会让 int4 的数值差出约 ±1 个百分点（例如 max|w|/7 的写法在 t5 下得到约 17%），不影响结论。
- 实测脚本：[`bench/gate.py`](../bench/gate.py)、[`bench/tf.py`](../bench/tf.py)，汇总见 [data/head8-analysis.md](data/head8-analysis.md)。
